---
name: hanig-swarm
description: >-
  Coordinate a swarm of agents to build projects autonomously on Slurm clusters.
  Use when dispatching, isolating, tracking or judging units of autonomous work
  across lambda/andromeda/chimera: a single Slurm job, a Nextflow or Snakemake
  pipeline, or a code-editing agent. Allocates an exclusive per-attempt write
  root so a cheap done-predicate is conclusive, binds a scheduler job to an
  attempt, and reports DONE / RUNNING / FAILED / PREEMPTED / INCOMPLETE. Use
  with the paseo skills for agent lifecycle; a code unit gets a per-attempt
  worktree and is judged here.

## Run logging (W&B, required)

Every training run must log to Weights & Biases (default entity `goodarzilab`, one W&B project per project named in the plan; see `hanig-wandb-logging`). Log per-step train loss, learning rate, gradient norm, throughput, GPU memory, every evaluation point, and final checkpoint selection, plus full W&B config (recipe/config and its hash, Git SHAs, model/data pins and hashes, seed, fold, hardware/node, scheduler/job IDs, checkpoint paths/hashes, and resume/attempt lineage). Obtain the W&B key from a secret store or per-run credentials (never in files, bundles, logs, or the repo); without egress, log offline and sync afterwards. Logging must not alter numerics; a training unit without W&B logging is incomplete unless explicitly waived by the owner.

## Default code agent and repair seeds

A `code` unit defaults to `default` in `agents.json` (override `provider`, `model`, or `thinking` on the unit; `thinking: null` suppresses the flag):
```json
{"id":"impl","kind":"code","repo":"/path","target_branch":"main",
 "prompt":"...","mode":"full-access"}
```
`mode` has no portable default: `codex` accepts `auto`, `auto-review`, or `full-access`; `claude` accepts `bypass` or `default`.

Optional code-unit `seed` is `{"ref": "refs/heads/...", "base": "<40/64-hex>", "head": "<40/64-hex>", "evidence": "<optional path>"}` (raw values; relative `evidence` resolves from the source repo). Before agent creation, the coordinator fetches from origin's push destination, verifies `base` ancestry to `head` and `head` reachability from `ref`, and persists the seed in launch intent (redispatch rechecks reachability and refuses changed provenance; historical attempts are never backfilled). The worker fetches, cherry-picks `-x -m 1 base..head` (first-parent mainline, skipping empties with `git cherry-pick --skip`, never whole-file checkout), and reads prior evidence. Temporary-ref cleanup failure warns without changing admission; refs are never reused. Reachability certifies neither conflict-free replay nor prior evidence, and seed changes no launch base, judging, scope, review, or closure.

## The one idea: isolation replaces attribution

Every attempt gets an exclusive, never-reused write root via `mkdir(exist_ok=False)` over pinned immutable inputs; Slurm cgroups isolate GPU and memory. For `slurm` ([Slurm evidence](references/slurm-evidence.md)):

    declared output exists in the attempt run-dir
      + coordinator-pinned pre-dispatch basis says it was absent or changed
      + terminal-OK execution evidence for this attempt
      == this unit produced it

Receipts and reports state `os_enforced_isolation:false` and `attribution_by_observation:false` unless a declared container profile was applied. Never restate a done predicate without its basis clause, and delete redundant process-observation attribution checks.

Optional enforced host-write surface for `slurm` or `pipeline`:
```json
"isolation":{"kind":"container","backend":"apptainer",
 "image":"/images/tool.sif","writable":["$SWARM_UNIT_DIR"],
 "read_only":["/shared/pinned/input.tsv"]}
```
The coordinator disables implicit home, cwd, hostfs, administrator, and requested binds, adds declared binds plus a writable tmpfs overlay, and accepts only one executable plus literal arguments (no shell, expansion, redirection, pipelines, or backgrounding). Only successful direct container execution writes the coordinator-held random token marker required alongside the pinned wrapper fact for `os_enforced_isolation:true`. The threat model covers careless workers and operators, not a malicious same-UID peer.

## Authority, verifiers, and code-attempt isolation

The checker returns its decision over an anonymous descriptor (`unit.run` refuses `pass_fds` below 3); `tests/test_record_is_not_authority.py` pins that rewriting `launch.json` changes no judging input. `REVIEW_PASS` means named reviewers failed to refute claims, not proof.

Before creating a code agent, the coordinator anchors `refs/heads/swarm-<attempt>`, raw and once-expanded origin push URL, immutable base commit/tree, generated branch, and `target_branch` (legacy `branch` is not a fallback), refusing an unreadable origin or pre-existing local/remote attempt branch. Judgment revalidates the route, fetches only that exact ref with submodules disabled (never rewriting `remote.origin.fetch`), and pins a clean descendant commit with a changed tree. A detached watcher best-effort invokes the locked `advance` path after terminal Paseo state (waiting at most 60s for the lock); scheduled `advance` remains the fallback and `unit.py check` remains the sole judge.

- **Verifier corpus:** exact regular-file limits are 10,000 paths, 256 MB per file, and 1 GB total; absent/empty corpus adds no Git reads or receipt fields.
- **Integration verifier (`integration-tests`):** runs a pinned verifier against a disposable no-commit merge into an explicit target commit with system/global Git config, hooks, filters, merge drivers, rerere, repo-selection vars, HOME/XDG, attributes/templates, executable path vars, and lazy/network fetch excluded. Branch-local receipts never satisfy `integration-tests`; policies that used that name for head-bound checks must rename or migrate them.
- **Worktree lifecycle & preservation:** each code attempt runs via Paseo `--cwd` in its coordinator-owned linked worktree (inode-bound for root, Git common dir, and linked Git dir; pre-inode launch facts retain path-only compatibility). Do not replace Paseo registry adoption checks with a lock. Before cleanup, the coordinator snapshots tracked and untracked bytes (excluding only the exact `.git` pointer matching its launch digest; replaced `.git` files/dirs/symlinks are preserved), verifies content digest and restore, and rechecks the source digest immediately before cleanup. Legacy records with absent path, remaining retries, and Paseo ownership may be annotated unrecoverable (exhausted cleanup skips annotation; ID-only records mark absent without lookup; path-only unowned records lack migration; annotations restore no bytes and confer no authority).

## Usage

Before review, workers run `scope-check PLAN --state-dir DIR --unit U --head REV --json` (from the attempt worktree: `--head "$(git rev-parse --verify HEAD^{commit})"`) and fix out-of-scope paths. JSON adds `head_source` (`worker` with `--head`, `judged` without it); only judged reports are admissible for merging (exit 0 in scope, 1 out of scope, 2 unchecked).
```bash
export HANIG_SWARM_DIR="/path/to/loaded/hanig-swarm"
U="$HANIG_SWARM_DIR/scripts/unit.py"
D=$(python3 "$U" allocate --root /external/swarm-runs --task align-reads --kind slurm --command "bwa mem ref.fa r1.fq r2.fq > out.bam" --output out.bam --input ref.fa --gpu-hours 4 --charge-to hani)
python3 "$U" bind "$D" --job-id 187196
python3 "$U" check "$D"
# DONE 0 | RUNNING 1 | FAILED 2 | PREEMPTED 3 | INCOMPLETE 4
```
Move an already queued job in place with `scontrol update JobId=187196 Partition=cpu`; cancel-and-redispatch leaves the new job id bound to nothing and edits the plan digest, forcing `--accept-plan-change`. Plan with `survey.py`'s reported accounts, QoS, memory, partitions, home, and filesystem facts ([field evidence](references/field-evidence.md)).

## The three kinds

| kind | isolation | done predicate |
|---|---|---|
| `slurm` | exclusive run-dir + allocation | pre-dispatch basis + terminal-OK owned scheduler evidence (or authorized exit record with confirmed queue absence) + outputs |
| `pipeline` | fresh work and publish dirs, boundary only | pre-dispatch basis + engine terminal exit + final outputs |
| `code` | per-attempt worktree while running; exact pushed ref for durable judgment | lifecycle settled + outputs + ref resolves to a committed tree change; merged PR closes |

Pipeline receipts state `basis.interior_judged:false`.
