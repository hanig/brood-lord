## Supported envelope and accepted limits

Secret redaction normalizes leaf keys (`lower()`, stripping `_ - .` and spaces) against `DEFAULT_SECRET_KEYS` plus caller `secret_keys` (excluding `RESERVED_KEYS`, which raises `ValueError` before SDK calls or writes; reserved config entries remain subject to the default secret list), pruning matching config/base_config entries before labels/metadata and recording dotted paths in `provenance.redacted_keys`. Metrics (including keys named `loss` or `password`) are not redacted and stay in W&B artifacts, cards, and summaries; newly added `secret_keys` on resume prune future entries with one path/earlier-exposure warning while prior labels remain (start a new `output_dir` with complete `secret_keys`). Explicit `run_name` labels and free text pass through caller-owned; `git_remote` drops userinfo/query/fragment and unparseable values become `null`. Complete key sets (`DEFAULT_SECRET_KEYS`, `RESERVED_KEYS`), container recursion, equality, and name-validation details live in [naming](references/naming.md).

- `"a.b"` and nested `a`/`b` deltas collide; avoid dotted keys.
- Pre-upgrade snapshots lack module/qualname identity (resume warns `legacy-types` and preserves old evidence; use a new `output_dir` for full identities).
- Interrupted snapshot writes can leave differing snapshots (`wandb_config.json` vs `wandb_config.backup.json`): next start refuses before init; preserve both and copy the intact snapshot over the other, or use a new `output_dir`.

## Read-only project audit

[audit_project.py](scripts/audit_project.py) reuses adjacent `wbkit` lint rules by file identity (`audit_project.audit(wandb.Api(), "entity/project", limit=200)` or `audit_project.main(wandb.Api())`). It omits internal `wandb-` prefixes, `run_table`, and `job`, selects the greatest numeric `vN` version (warning and falling back to the first version if `vN` metadata is absent), propagates API errors, names unreadable archives, and edits no runs or artifacts.
