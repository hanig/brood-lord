# hanig-wandb-logging

## Host capability boundary

Use the active host's real file and shell capabilities and authorized W&B
access. This skill installs no package, credentials, connector or service.
The caller installs and imports W&B in its own project and passes it to wbkit.
Measured with wandb 0.31.0; other versions are best effort. Missing access is
reported as an incomplete logging check.

Set `HANIG_WANDB_LOGGING_DIR` to the directory holding this loaded SKILL.md.
Copy [wbkit](scripts/wbkit.py) from there into the training project. Inputs
and outputs stay relative to the project directory.

This skill makes runs readable. It never decides whether a run succeeded or
converged. Verdicts come from hanig-verified-workflow contracts and
hanig-swarm/converge.py predicates. The `Expect:` line quotes the predicate
declared before the run. A checkpoint chosen after seeing results is labeled
post hoc in the card's caveats. `finish` records the caller-supplied verdict.
The training logging requirement lives in hanig-project and hanig-swarm;
this skill explains how to apply it.

## Workflow

1. Read the entry point, config, distributed rank setup and existing logging.
2. Show a concrete plan: entity/project, group, name, H:/Expect: notes, config,
   step axis, metrics and summaries. Resolve new shared naming choices once.
3. Vendor wbkit, then wire it into project code. See [naming](references/naming.md)
   and [frameworks](references/frameworks.md).
4. Run an offline smoke check before launch. Inspect lint output, config,
   provenance, metric axes and resume behavior; report what was observed.

```python
import wandb  # installed by the training project
import wbkit

run = wbkit.start_run(wandb,
    project="sample-pretrain", family="sample", job_type="train",
    model="sample", data="cells",
    hypothesis="The new recipe lowers held-out loss.",
    expect="val/loss < 0.5",  # quote the predeclared predicate
    config={"arch": arch_cfg, "train": train_cfg, "data": data_cfg},
    base_config=base_cfg, group="20261110-recipe-ablation",
    summaries={"val/loss": "min", "val/score": "max"},
    output_dir=out_dir)
wbkit.log_step(run, step, {"train/loss": loss, "opt/lr": lr})
wbkit.finish(run, outcome=contract_result, verdict=contract_verdict)
```

Nonzero ranks receive disabled runs. Keep each logical run's `output_dir`
separate and reuse it across requeues. It stores the stable id, sanitized
launch config/provenance and resume count. Resume preserves the launch config;
start a new output directory for a different experiment. Restore the actual
training checkpoint separately and log its optimizer step.

The sanitizer removes values under credential-pattern keys, JSON-valued argv,
labeled secret assignments and URL userinfo. It cannot recognize unlabeled
credentials in prose. Inspect custom text before sending it. Direct SDK calls
outside wbkit are the caller's responsibility.

Names and note length are recommendations. Lint warnings do not refuse valid
SDK names or notes. `finish` appends `Outcome (verdict):`, prints lint advice,
and closes the run; it does not calculate a verdict.
