## Canonical behavior declarations

This section is generated by `scripts/declaration_registry.py` from
`declarations.json`; edit the registry, then run `write-body`.

- **`logging.conventions`:** Use model-data-delta-seed names, H:/Expect:/Outcome notes, family/arch/train/data/provenance, namespaced metrics/summaries, rank-zero logging and stable ids. Slugs/note length are advice. (Elaboration: [naming.md](references/naming.md), [frameworks.md](references/frameworks.md).)
- **`logging.boundary`:** Never judge success/convergence. Record caller verdicts from hanig-verified-workflow contracts and hanig-swarm/converge.py predicates. Expect quotes the predeclared predicate. Mark post-result checkpoints post hoc in card caveats.
- **`capability.host`:** Use authorized access and caller-supplied W&B; scripts use stdlib. Missing access leaves logging evidence incomplete.
- **`paths.skill-directory`:** Set HANIG_WANDB_LOGGING_DIR to the loaded SKILL.md directory; data/output stay project-relative.
- **`logging.credentials`:** Record only program basename, flags and positional count for commands, with no digest; omit values except option-shaped tokens before --, recorded by the flag rule. Mask secret-keyed config values recursively and their verbatim values of at least 6 characters in sent strings. Never put credentials in notes or names; use the environment, never config. Free text is not otherwise scanned. (Elaboration: [naming.md](references/naming.md).)
- **`approval.shared-state`:** Show a logging plan; confirm shared naming/edits. Never delete runs/artifact versions as cleanup.

```python
import wandb, wbkit  # caller-installed W&B
run = wbkit.start_run(wandb, **run_args)
wbkit.log_step(run, step, metrics)
wbkit.finish(run, outcome, contract_verdict)
```

run_args: project/family/job_type/model/data, hypothesis/expect, nested config;
optional base_config/group/output_dir/summaries (min/max).

Reuse output_dir across requeues; new experiments need new directories.
It saves sanitized config/provenance, original name/notes, id and resume count.
Restore training checkpoints separately. Direct SDK writes remain caller-owned.

Supply the original name/hypothesis/expect for legacy state missing these fields;
the helper warns when it cannot reconstruct them.
A ready marker records completed metadata, before SDK initialization.
Both unreadable config snapshots cause refusal before SDK init, leaving both
files unchanged. Recovery is an operator action: restore a known-good
`wandb_config.json` from backup, or start a new run id in a new output_dir.
Lost ready snapshots also require that recovery. Corrupt bytes are kept.
The marker guards new runs only. Legacy metadata predating it, or deleted by
hand, resumes with caller config if both snapshots are absent. Restore the
snapshot before resuming, or start a new run id.
Option-shaped values before `--` follow the flag rule; omit such values or
place positionals after `--` when that syntax is supported by the caller.

Resume warns when caller config differs from the saved logging config.

Supported envelope amendment (orchestrator, 2026-11-10): free text in notes,
hypothesis, names and summary strings is not scanned for credential labels.
Secrets absent from secret-keyed config are sent as written; values shorter
than 6 characters are masked in config only. Never put credentials in notes
or names. Pass credentials through the environment, never through config.
Option-shaped values and unmarked legacy recovery retain the limits above.
