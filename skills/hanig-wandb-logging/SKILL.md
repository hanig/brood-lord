# hanig-wandb-logging

## Host capability boundary

Measured with wandb 0.31.0; other versions are best effort. This skill installs
no package, connector, credentials or service.

Set `HANIG_WANDB_LOGGING_DIR` to the directory containing this loaded SKILL.md.
Copy [wbkit](scripts/wbkit.py) from that directory into the training project.
For audits, add its `scripts` directory to the caller's `sys.path`; project
input and output paths remain relative to the project directory.

`finish` records a caller-supplied verdict. The training logging policy lives
in hanig-project and hanig-swarm; this skill explains how to apply it.

## Canonical behavior declarations

This section is generated by `scripts/declaration_registry.py` from
`declarations.json`; edit the registry, then run `write-body`.

- **`logging.conventions`:** Follow the references: model-data-delta-seed names; H:/Expect:/Outcome notes; family/arch/train/data/provenance config; namespaced metrics on one step axis with summaries; artifact cards, metadata and pinned lineage; rank-zero logging and persistent requeue ids. (Elaboration: [naming.md](references/naming.md), [artifacts.md](references/artifacts.md), [frameworks.md](references/frameworks.md).)
- **`logging.boundary`:** Never judge success or convergence. Record verdicts from hanig-verified-workflow contracts and hanig-swarm/converge.py predicates. Expect quotes the predicate declared before the run. Label post-result checkpoint selection post hoc in card caveats.
- **`capability.host`:** Use available host capabilities and authorized W&B access. Callers pass W&B or Api explicitly; shipped scripts import only stdlib. Missing access blocks the logging check.
- **`paths.skill-directory`:** Set HANIG_WANDB_LOGGING_DIR to the loaded SKILL.md directory; locate programs there and keep data/output paths project-relative.
- **`logging.credentials`:** Never send config values under secret-pattern keys or use them in generated names/notes. Redact argv credentials; check custom free text.
- **`approval.shared-state`:** Show a concrete logging plan; resolve new project/entity/group choices with the user. Show exact run renames, notes/tags rewrites, shared card edits or registry promotions and obtain confirmation first. Never delete runs or artifact versions as cleanup.

## Workflow

### 1. Survey before editing

Read the training entry point to find:

- Framework: PyTorch, Lightning, HF Trainer, Accelerate, JAX. See
  [frameworks](references/frameworks.md).
- Config system (Hydra, OmegaConf, argparse, dataclass, YAML) and where the
  seed lives.
- Data inputs: paths, URIs, sizes, whether they already exist as artifacts.
- Checkpointing: cadence, where files go, how "best" is decided.
- Distribution and scheduler: DDP/FSDP ranks, Slurm requeue or preemption.
- Existing W&B calls: keep anything that already follows the conventions.

### 2. Write a logging plan and show it

Before editing, show a plan with concrete strings:

```
entity/project  arc-ml/state3-pretrain
group           20261109-mask-ratio-ablation
job_type        train
run name        state3-tahoe100m-mask0.3-s0 (deltas vs base)
tags            ablation, data:tahoe100m
notes           H: 30% masking beats 15% on held-out cell lines.
                Expect: val/pearson_delta +0.02 or more.
step axis       trainer/step (optimizer steps)
metrics         train/loss, val/loss[min], val/pearson_delta[max], opt/lr,
                opt/grad_norm, perf/samples_per_s, perf/gpu_mem_gb
inputs          arc-ml/state3-pretrain/tahoe100m-hvg2k:v3
outputs         ckpt-<run_id>, aliases step-N/best, every 5k steps;
                preds-<run_id>-replogle-k562, at end
```

Infer project/entity/group from `audit_project.audit(wandb.Api(), "entity/project")`
or `wandb.Api().projects(entity)`; otherwise propose and confirm once, then apply.

### 3. Implement

Vendor [scripts/wbkit.py](scripts/wbkit.py), then wire it in. Minimal raw-PyTorch shape:

```python
import wandb  # installed by the training project
import wbkit

run = wbkit.start_run(wandb, 
    project="state3-pretrain", family="state3", job_type="train",
    model="state3", data="tahoe100m",
    hypothesis="Masking 30% of genes beats 15% on held-out cell lines.",
    expect="val/pearson_delta +0.02 or more",
    config={"arch": arch_cfg, "train": train_cfg, "data": data_cfg},
    base_config=base_cfg,                 # the group's reference config
    group="20261109-mask-ratio-ablation",
    tags=["ablation", "data:tahoe100m"],
    summaries={"val/loss": "min", "val/pearson_delta": "max"},
    output_dir=out_dir,                   # stable id across Slurm requeues
)
ds = wbkit.use_input(run, "arc-ml/state3-pretrain/tahoe100m-hvg2k:v3")
...
wbkit.log_step(run, step, {"train/loss": loss, "opt/lr": lr, "perf/samples_per_s": sps})
...
wbkit.log_model(wandb, run, ckpt_path, step=step, metrics={"val/loss": vl}, is_best=vl < best)
...
wbkit.finish(run, outcome="val/pearson_delta +0.031 at 40k steps; 3 seeds agree.",
             verdict="supported")
```

Nonzero ranks receive disabled runs; metric calls need no guards. `finish`
appends the outcome, sets `summary.verdict`, prints lint and closes the run.

### 4. Verify with a smoke run

Before launch, run a few steps with `WANDB_MODE=offline` (or debug flag and
`job_type="debug"`). Check `finish` lint, readable names, `arch/train/data` and
`provenance.git_commit`, namespaced keys and rendered cards. Keep `output_dir`
outside Git or ignored to avoid `dirty-tree`. Report observed smoke results.

### 5. Clean up an existing project

From a caller that imports W&B, the read-only audit is:

```python
import wandb, audit_project
report = audit_project.audit(wandb.Api(timeout=120), "entity/project", 200)
```

It groups problems by rule code (`name.random`, `notes.empty`,
`artifact.thin-card`, ...). Propose fixes with exact before/after values for
confirmation under `approval.shared-state`; tag failures `broken` instead of deleting.

## Failure modes to catch in review

- Per-rank `wandb.init`: duplicates or interleaved runs.
- Backward `run.log(step=...)` on resume: silently dropped points; use `trainer/step`.
- Missing `define_metric`: validation uses internal steps, misaligning curves.
- Lightning `log_model=True` or HF `WANDB_LOG_MODEL`: anonymous checkpoint cards;
  disable them and use `wbkit`.
- Large uploads: use references above 2 GiB; state host/mount in caveats.
- Config/argv secrets: wbkit redacts credential keys; check custom fields too.
- `latest` means newest, never best.

## Querying afterwards

Read best runs, curves and sweep summaries with `wandb/skills` `wandb-primary`.
Filter by `group`, `job_type`, `tags`, `summary_metrics.verdict`, `config.train.*`.
