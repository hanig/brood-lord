Never run `review.py` or `committee.py` on your own diff: the author is not its own reviewer, and the gate runs where the orchestrator runs. The orchestrator runs the loaded review gate from its own Lor session (`LOR_SESSION_ID` present) using `{{REVIEW_ENVIRONMENT}}`, the host's authorized credential-loading mechanism, without printing secrets. <!-- declaration: delegation.preamble -->

## Supported envelope

Every task must carry a section headed "Supported envelope and accepted limits". The orchestrator passes it unchanged into review context and marks any later amendment explicitly. Do not tell reviewers to stop reporting anything: an excluded trigger can have consequences inside the envelope. Repair every reproduced finding inside the envelope and hand off again within the round bound. <!-- declaration: delegation.preamble -->

A finding whose trigger is outside the declared envelope, whose failure is bounded and diagnosable, and which loses no work is reproduced and recorded in `evidence.md` with its consequence and a written operator recovery, not repaired. This does not permit overriding hard constraints, required evidence or outputs, authority or isolation boundaries, shared guards or candidate-merge checks. When only those eligible out-of-envelope findings remain open, commit and push to the anchored attempt branch, open no PR, and stop for orchestrator adjudication under `docs/orchestrator-mandate.md`. The completion protocol takes precedence if it requires a separate recovery ref. <!-- declaration: delegation.preamble -->

For Codex code agents only, wait in one blocking harness call whenever it covers the run. In this session, `exec_command` clamps `yield_time_ms` to 30,000 ms (requests of 30,000, 300,000 and 1,800,000 all returned at about 30 s). With code mode available, use one `functions.exec` call with `// @exec: {"yield_time_ms": 1800000}` for a run expected to finish within 30 minutes: await `tools.exec_command({cmd: COMMAND, yield_time_ms: 30000})`, then, only while its result has a `session_id`, await `tools.write_stdin({session_id: result.session_id, chars: "", yield_time_ms: 300000})` and retain each result's output. These internal waits do not require another model call. Set the outer yield to cover the expected run; if the outer cell yields, resume it with `functions.wait` at the maximum duration accepted by that tool. Without code mode, the 30 s command cap forces polling: use empty `write_stdin` calls with `yield_time_ms: 300000`, the measured maximum, until completion. Never use repeated `sleep` calls to wait on a running command, or `write_stdin` checks except when a measured cap forces polling; every such poll waits the maximum measured duration. Re-probe after a harness change rather than assuming these limits apply to another version. Other providers retain their existing waiting instructions. <!-- declaration: delegation.preamble -->
